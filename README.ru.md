## Зачем это

Прокси видит трафик Minecraft как обычный TCP. MC Tunnel ставит между игрой и
прокси маленький локальный посредник: игра думает, что играет с
`127.0.0.1:25565`, а на самом деле соединение уходит через прокси на нужный
сервер. Полезно, когда до сервера напрямую не достучаться, а прокси есть.

```
Minecraft ──TCP──> 127.0.0.1:25565 ──MC Tunnel──> SOCKS5 / HTTP прокси ──> сервер
```

Это не просто перекладывание байтов: туннель **переписывает адрес в handshake
Minecraft** на настоящий сервер, поэтому клиенту не нужно знать о прокси. Если
первым пакетом пришёл не handshake (например, legacy ping `0xFE`), трафик
проходит байт в байт.

## Возможности

- **SOCKS5** (RFC 1928, с авторизацией) и **HTTP CONNECT** (Basic auth).
- **Проверка прокси** одной кнопкой: сначала внешний IP через прокси, затем
  настоящий server list ping до сервера. Видно, что сервер реально отвечает, а
  не только что прокси принимает соединения.
- **Живой журнал**: подключения, объём трафика, ошибки прокси. Длинные строки
  переносятся, а не обрезаются.
- **Настройки сохраняются** между запусками; пароль прокси шифруется Windows
  DPAPI и не лежит в файле открытым текстом.
- **Одно окно, без консоли**: GUI-подсистема, вся диагностика в журнале.
- **Свой интерфейс**: тёмная тема, шрифт Inter внутри exe, свечение за курсором,
  скруглённые углы, иконка приложения.

## Как пользоваться

1. Скачать `MC-Tunnel.exe` из [Releases](../../releases) и запустить.
2. **Minecraft сервер** — `host` или `host:port` (по умолчанию порт 25565).
3. **Прокси** — одной строкой, протокол берётся из схемы:
   - `socks5://user:pass@host:1080`
   - `http://user:pass@host:8080`
   - `user:pass@host:1080` — без схемы, тогда протокол из переключателя
   - `host:1080` — без авторизации
   - `host:1080:user:pass` — старый формат «через двоеточия»
4. **Проверить прокси** — убедиться, что прокси живой и сервер через него
   отвечает. Поле сервера при этой проверке можно оставить пустым.
5. **Запустить** и в Minecraft подключиться к `127.0.0.1:25565`.

Порт локального прослушивания можно изменить. Слушаются оба loopback-адреса,
поэтому `localhost` в игре работает и по IPv4, и по IPv6 — что выберет клиент.

## Где хранятся настройки

- По умолчанию `%APPDATA%\mctunnel\config.json`.
- Если профиль недоступен на запись — папка с exe, затем `%TEMP%\mctunnel`.
  Выбранный путь всегда пишется в журнал.
- Переменная `MCTUNNEL_CONFIG` задаёт путь жёстко и никогда не подменяется молча.
- Пароль прокси хранится зашифрованным через DPAPI, привязанным к учётной
  записи Windows: перенести конфиг на другую машину «как есть» не получится.
- Запись атомарная (временный файл → `fsync` → переименование), поэтому
  оборванный запуск не оставит половинчатый конфиг. Битый файл сохраняется как
  `config.json.bak`, приложение стартует с чистой формой.

## Технические детали

**Слои.** Каждый знает только про соседний:

```
main.go / app.go     окно Wails и биндинги для страницы
frontend/dist        HTML/CSS/JS интерфейса, без сборщика
internal/tunnel      listener, сессии, счётчики, жёсткий Stop
internal/relay       транспорт: tcp.go (Java), udp.go (заглушка под Bedrock)
internal/proxy       протоколы и проверка: socks5.go, http.go, check.go
internal/mcnet       переписывание handshake, server list ping
internal/serverprobe проверка сервера через прокси
internal/settings    конфиг: схема с версией, атомарная запись
internal/secret      Windows DPAPI
internal/applog      журнал в памяти + подписка для окна
```

## Сборка

Нужны Go 1.25 и CLI Wails:

```cmd
go install github.com/wailsapp/wails/v2/cmd/wails@latest
wails build -s -m
```

- `-s` — фронтенд уже собран, npm не нужен;
- `-m` — без `go mod tidy`, зависимости зафиксированы.

Готовый exe появляется в `build\bin`. Сборка идёт **без cgo**: ни компилятора
C, ни внешних DLL не требуется — туннель, прокси и настройки это чистый Go.

Проверки перед коммитом:

```cmd
go vet ./...
go test ./...
```

Старый Win32-интерфейс (`cmd/mctunnel`, `internal/ui`) остаётся в дереве и
собирается через `build.cmd` — на случай, если понадобится сравнить поведение.

## Ограничения

- Только Windows x64 и только Minecraft **Java**. Bedrock/UDP сознательно не
  поддерживается.
- Нет SRV: если сервер живёт по `_minecraft._tcp` записи, порт нужно узнать
  самому. Клиент Minecraft делает это за вас, туннель — нет.
- Окно фиксированного размера (960×440) и не разворачивается: вёрстка
  рассчитана ровно на него.
- На Windows 10 скругление углов идёт через регион окна, кромка ступенчатая; на
  Windows 11 окно скругляет композитор.
- Нужен WebView2: в Windows 11 он есть, в Windows 10 обычно приходит с Edge.
